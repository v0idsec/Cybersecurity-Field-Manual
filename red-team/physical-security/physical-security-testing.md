# Physical Security Testing

A reference for conducting controlled physical security tests during authorised assessments.

Physical testing should validate whether security controls work as intended without introducing unnecessary risk to people, facilities, equipment or business operations.

## Assessment principles

- Obtain written authorisation.
- Follow the agreed rules of engagement.
- Use designated test locations and credentials.
- Avoid destructive or intrusive techniques.
- Do not interfere with emergency systems.
- Maintain communication with the assessment contact.
- Stop when an unexpected safety or operational issue arises.
- Document all test activity.

## 1. Test planning

Before testing, establish:

- Assessment objectives.
- Approved facilities.
- Approved test areas.
- Test dates and hours.
- Permitted activities.
- Prohibited activities.
- Designated test credentials.
- Client contacts.
- Emergency procedures.
- Evidence requirements.
- Stop conditions.

Where appropriate, notify relevant security and facilities personnel.

## 2. Perimeter testing

Potential test objectives:

- Verify that boundary controls are maintained.
- Confirm that designated entrances are clearly identified.
- Review vehicle and pedestrian access procedures.
- Validate external lighting and monitoring.
- Confirm that security inspections are documented.

Do not attempt to breach physical barriers or enter unauthorised areas.

## 3. Access-control testing

Use designated test credentials.

Possible test cases:

| Test | Expected result |
|---|---|
| Valid test credential | Access granted to approved area |
| Expired test credential | Access denied |
| Revoked test credential | Access denied |
| Unauthorised area | Access denied |
| Temporary credential after expiry | Access denied |
| Approved access event | Event recorded correctly |

Document the expected and observed result for each test.

## 4. Visitor management testing

With client approval, conduct a controlled visitor workflow assessment.

Review:

- Visitor registration.
- Host approval.
- Identity verification.
- Temporary badge issuance.
- Visitor escort requirements.
- Visitor departure procedures.
- Record retention.

Use an approved test identity and do not impersonate an uninvolved employee or contractor.

## 5. Locking and entry system testing

Review approved documentation and designated test hardware.

Possible tests:

- Verify electronic lock operation.
- Confirm authorised credential behaviour.
- Review emergency release documentation.
- Verify maintenance and inspection records.
- Confirm access events are recorded.

Do not force doors, manipulate live locks or interfere with emergency egress.

## 6. Surveillance testing

Use approved test scenarios to validate:

- Camera recording.
- Event timestamps.
- Recording retrieval.
- Monitoring responsibilities.
- Alarm notifications.
- Incident escalation.

The client should approve any test event that could generate a security response.

## 7. Alarm testing

Alarm testing must be coordinated with the responsible security team.

Confirm:

- The test window.
- The alarm type.
- The monitoring contact.
- The expected notification.
- The escalation procedure.
- The process for returning the system to normal operation.

Never trigger alarms without prior approval.

## 8. Restricted-area testing

Use designated test areas and approved access arrangements.

Validate whether:

- Access permissions are appropriate.
- Entry is logged.
- Visitor restrictions are enforced.
- Monitoring systems record approved test events.
- Security personnel understand escalation procedures.

Do not attempt entry into live restricted areas outside the approved scope.

## 9. Physical social engineering

Physical social engineering is a separate, high-risk assessment activity.

It may involve approved tests of:

- Visitor verification.
- Staff security awareness.
- Contractor identification.
- Reception procedures.
- Security escalation.

It requires explicit written authorisation and agreed scenarios.

Do not use coercion, threats, harassment or unauthorised collection of personal information.

See [Social Engineering](../social-engineering/README.md).

## 10. Evidence collection

Record:

- Test ID.
- Date and time.
- Location.
- Assessor.
- Test objective.
- Expected result.
- Observed result.
- Supporting evidence.
- Client contact.
- Outcome.
- Follow-up action.

Evidence should be relevant, proportionate and securely stored.

## 11. Safety and operational controls

Stop testing if:

- An emergency occurs.
- A safety system is affected.
- An uninvolved person becomes involved.
- Access extends beyond the agreed scope.
- A business-critical system is disrupted.
- The client requests that testing stop.

Do not leave doors, gates, alarms or access systems in an altered state.

## 12. Reporting

Each finding should include:

- Finding title.
- Affected facility or control.
- Severity.
- Description.
- Expected behaviour.
- Observed behaviour.
- Evidence.
- Business impact.
- Likelihood.
- Remediation.
- Retest criteria.

## 13. Retesting

Retest only the agreed controls.

Confirm:

- The original weakness is addressed.
- The revised control works as intended.
- Related processes are updated.
- Evidence supports remediation.
- No new safety or operational issues were introduced.
