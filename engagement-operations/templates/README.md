# Assessment and Reporting Templates

A collection of reusable templates for documenting vulnerabilities, security bugs and professional cybersecurity assessment engagements.

These templates are designed to provide consistent, structured reporting across different assessment types.

## Available Templates

| Template | Purpose |
|---|---|
| [Bug Report](bug-report-template.md) | Concise report for an individual bug or security issue |
| [Vulnerability Report](vulnerability-report-template.md) | Detailed technical vulnerability documentation |
| [Network Pentest Report](network-pentest-report-template.md) | Full network penetration testing deliverable |
| [Web Application Pentest Report](web-app-pentest-report-template.md) | Full web application security assessment deliverable |
| [Physical Security Assessment](physical-security-assessment-template.md) | Physical facility and access-control assessment deliverable |

## Choosing the Right Template

- **Bug Report:** Use when reporting a discrete issue through a bug tracker, vulnerability disclosure programme or internal ticketing system.
- **Vulnerability Report:** Use when documenting an individual security vulnerability in detail.
- **Network Pentest Report:** Use for a complete internal or external network assessment.
- **Web Application Pentest Report:** Use for a complete web application or API assessment.
- **Physical Security Assessment:** Use when reporting physical facility, access-control or environmental security weaknesses.

## Usage

1. Copy the relevant template.
2. Replace all placeholder fields.
3. Remove sections that are not applicable.
4. Include supporting evidence.
5. Validate technical details and reproduction steps.
6. Review severity and business impact.
7. Ensure sensitive information is appropriately redacted.
8. Complete a final quality review before submission.

## Reporting Principles

All reports should be:

- Accurate and evidence-based.
- Reproducible where applicable.
- Clear to both technical and non-technical audiences.
- Proportionate in severity.
- Focused on business and security impact.
- Actionable, with practical remediation guidance.
- Free from unnecessary sensitive information.

Never include live credentials, access tokens, private keys or unnecessary personal information in reports.
