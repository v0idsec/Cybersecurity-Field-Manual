# Browser and Email Forensics

## Overview

Browser and email artefacts can help reconstruct phishing incidents, suspicious downloads, account compromise, data exposure and user activity.

Relevant sources include:

- Browser history
- Download databases
- Cookies
- Cache
- Saved sessions
- Autofill data
- Bookmarks
- Email messages
- Email headers
- Attachments
- Mailbox audit records
- Email gateway logs

## Browser Forensics

Modern browsers store information in databases and profile directories.

### Chromium-Based Browsers

Examples include:
- Google Chrome
- Microsoft Edge
- Brave
- Chromium

Common profile artefacts include:

```text
History
Cookies
Login Data
Web Data
Bookmarks
Preferences
```

Locations vary by operating system and browser profile.

### Firefox

Common artefacts include:

```text
places.sqlite
cookies.sqlite
formhistory.sqlite
logins.json
key4.db
```

Firefox profile data is typically stored in a user-specific application directory.

## Browser History

History databases may contain:
- Visited URLs
- Visit timestamps
- Visit counts
- Download records
- Referrer information

Investigative questions:
- Was a phishing URL visited?
- Was a file downloaded?
- Did the browser access an external service?
- Was a suspicious redirect followed?
- Did the activity occur before or after malware execution?

History records can be deleted or altered.

## Download Analysis

Review:
- Download URL
- Local file path
- Download timestamp
- File name
- File type
- File hash
- Browser metadata

Correlate downloaded files with endpoint telemetry and email attachments.

## Cookies and Sessions

Cookies may contain session identifiers and other authentication-related information.

Treat browser profiles as sensitive evidence.

Do not use extracted session material to access accounts unless explicitly authorised as part of a controlled investigation.

## Browser Cache

Cache may contain:
- Web resources
- Images
- Scripts
- Cached documents
- Partial content

Cache contents may help reconstruct visited pages, but caching behaviour varies and absence of content is not proof that a page was never visited.

## Email Forensics

Email investigations commonly examine:

- Sender and recipient
- Subject
- Message ID
- Delivery path
- Authentication results
- Attachments
- Embedded URLs
- Timestamps
- Mailbox rules
- Forwarding configuration

## Email Headers

Important headers include:

| Header | Purpose |
|---|---|
| From | Displayed sender address |
| Return-Path | Envelope sender information |
| Reply-To | Reply destination |
| Received | Mail server delivery path |
| Message-ID | Message identifier |
| Authentication-Results | SPF, DKIM and DMARC results |
| Date | Sender-provided message date |
| X-Originating-IP | Potential originating IP, if present |

Headers may be missing, modified or generated by intermediate systems.

## SPF, DKIM and DMARC

### SPF

Sender Policy Framework checks whether a sending host is authorised by the domain's SPF policy.

### DKIM

DomainKeys Identified Mail uses cryptographic signatures to help verify message integrity and domain association.

### DMARC

Domain-based Message Authentication, Reporting and Conformance defines how SPF and DKIM results are evaluated against domain alignment and policy.

Authentication success does not guarantee that a message is legitimate. Compromised legitimate accounts can send malicious email.

## Attachment Analysis

For suspicious attachments:

1. Preserve the original message.
2. Extract attachments using an approved process.
3. Calculate hashes.
4. Identify actual file types.
5. Review metadata.
6. Check reputation using approved services.
7. Perform static analysis.
8. Use an isolated sandbox if authorised.
9. Correlate with endpoint telemetry.

Do not open suspicious attachments on a production workstation.

## Mailbox Compromise

Investigate:
- Unexpected inbox rules
- External forwarding
- Delegated mailbox access
- Suspicious sign-ins
- OAuth application grants
- New authentication methods
- Sent items
- Deleted items
- Unusual message access

Correlate mailbox events with identity provider and endpoint logs.

## Example: Inspect an Email Header

Save the original message as `.eml` where supported.

Review headers:

```bash
grep -Ei \
'^(From|To|Reply-To|Return-Path|Received|Message-ID|Authentication-Results):' \
message.eml
```

This is a basic extraction aid, not a complete email-header parser.

## Example: Hash an Attachment

```bash
sha256sum suspicious-attachment
```

PowerShell:

```powershell
Get-FileHash .\suspicious-attachment -Algorithm SHA256
```

## Investigation Workflow

1. Preserve the original message.
2. Collect relevant mailbox and gateway records.
3. Review message headers.
4. Validate authentication results.
5. Extract and hash attachments.
6. Identify URLs and redirects.
7. Review browser history and downloads.
8. Examine endpoint execution telemetry.
9. Investigate mailbox rules and forwarding.
10. Correlate identity activity.
11. Document findings.

## Common Mistakes

- Trusting the display name.
- Assuming SPF success proves legitimacy.
- Ignoring Reply-To mismatches.
- Failing to preserve the original message.
- Opening attachments outside an isolated environment.
- Treating browser history as complete.
- Ignoring session and OAuth activity.
- Failing to correlate email with endpoint evidence.
