# Security Awareness Programme

## Overview

A security awareness programme is a structured approach to educating employees, contractors and other relevant stakeholders about organisational security risks and expected behaviours.

The programme should align with the organisation's risk profile, security policies, operational requirements and regulatory obligations.

## Programme Objectives

Typical objectives include:

- Reduce susceptibility to common social engineering attacks.
- Improve reporting of suspicious activity.
- Improve password and authentication practices.
- Reduce accidental data disclosure.
- Improve understanding of security policies.
- Build confidence in incident reporting.
- Support compliance obligations.
- Improve security behaviour across the organisation.

## Programme Governance

Define responsibility before launching the programme.

| Role | Responsibility |
|---|---|
| Executive sponsor | Approves objectives and resources |
| Security team | Owns security content and programme direction |
| Awareness coordinator | Manages delivery and reporting |
| Human Resources | Supports training administration |
| IT team | Supports technical education and reporting channels |
| Managers | Reinforce expectations within teams |
| Employees | Participate and follow security procedures |

Responsibilities should be documented and approved.

## Programme Development Lifecycle

### 1. Assess Current Maturity

Review:

- Existing training.
- Security policies.
- Incident trends.
- Phishing reports.
- Employee feedback.
- Previous awareness campaign results.
- Regulatory and contractual requirements.

Identify gaps and prioritise areas of risk.

### 2. Identify Target Audiences

Different roles have different security responsibilities.

Examples:

| Audience | Priority Topics |
|---|---|
| All employees | Phishing, passwords, reporting |
| Executives | Business email compromise, impersonation |
| Finance | Payment fraud, invoice manipulation |
| HR | Personal information, recruitment scams |
| IT administrators | Privileged access, social engineering |
| Developers | Secure coding, secrets management |
| Remote workers | Device security, network safety |
| Customer support | Identity verification, information disclosure |

### 3. Establish Learning Objectives

Objectives should be measurable.

Weak objective:

- Employees will understand phishing.

Better objective:

- Employees will be able to identify common phishing indicators and locate the approved reporting process.

### 4. Select Delivery Methods

Possible methods:

- Short online modules.
- Instructor-led sessions.
- Internal newsletters.
- Posters and quick-reference guides.
- Security bulletins.
- Tabletop exercises.
- Authorised phishing simulations.
- Department-specific workshops.
- Short knowledge checks.

Use multiple methods to reinforce learning.

### 5. Establish a Schedule

An example annual programme:

| Period | Topic |
|---|---|
| January | Passwords and MFA |
| February | Phishing awareness |
| March | Data handling |
| April | Safe browsing |
| May | Remote working |
| June | Incident reporting |
| July | Business email compromise |
| August | Privacy and personal information |
| September | Physical security |
| October | Cybersecurity awareness campaign |
| November | Mobile device security |
| December | Annual review and lessons learned |

Adjust the schedule to current threats and organisational needs.

### 6. Deliver and Reinforce

- Publish training through approved channels.
- Provide accessible materials.
- Communicate expectations.
- Make reporting procedures easy to find.
- Provide additional support where needed.
- Record completion where required.

### 7. Measure and Improve

Evaluate:

- Completion rates.
- Knowledge assessment results.
- Reporting rates.
- Incident trends.
- Employee feedback.
- Behavioural improvements.
- Coverage across departments.

Use results to update the programme.

## Programme Documentation

Maintain:

- Programme objectives.
- Scope and audience.
- Approved content.
- Training schedule.
- Attendance and completion records.
- Campaign approvals.
- Measurement criteria.
- Feedback.
- Review records.
- Improvement actions.

## Privacy and Employment Considerations

Awareness programmes may involve employee data and behavioural measurement.

Before collecting or analysing individual-level information:

- Obtain appropriate organisational approval.
- Consult relevant privacy and employment requirements.
- Clearly communicate programme expectations.
- Restrict access to training records.
- Define retention periods.
- Avoid unnecessary collection of personal information.
- Ensure simulations do not collect real passwords or authentication codes.

## Programme Review

Review the programme at least annually and after significant incidents or organisational changes.

Consider:

- New attack techniques.
- Changes to business processes.
- New technology.
- Updated regulatory requirements.
- Changes in employee behaviour.
- Lessons from incident response.

## Key Takeaways

An effective awareness programme is risk-driven, role-specific and continuously improved.

The goal is not simply to make employees complete training. The goal is to help them make safer decisions and report problems early.
