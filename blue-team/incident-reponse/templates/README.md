# Incident Response Templates

Reusable documentation for security incident triage, investigation, response coordination and post-incident improvement.

## Templates

| Template | Purpose |
|---|---|
| [Incident Report](incident-report-template.md) | Record the incident from initial detection through closure |
| [Incident Triage](incident-triage-template.md) | Capture initial assessment, severity and escalation decisions |
| [Incident Response Plan](incident-response-plan-template.md) | Coordinate response activities, responsibilities and decisions |
| [Incident Communications](incident-communications-template.md) | Record and prepare approved incident communications |
| [Post-Incident Review](post-incident-review-template.md) | Conduct a blameless post-mortem and document lessons learned |
| [Lessons Learned Action Register](lessons-learned-action-register-template.md) | Track corrective actions through verified completion |

## Usage

1. Copy the relevant template into the organisation's approved incident documentation location.
2. Assign a unique incident reference.
3. Complete the relevant sections using verified information.
4. Mark unknown or unconfirmed information explicitly.
5. Restrict access according to the sensitivity of the incident.
6. Retain records in accordance with organisational policy.

## Documentation principles

- Use a consistent timezone throughout the incident record.
- Distinguish confirmed facts from assumptions.
- Reference evidence rather than duplicating sensitive material unnecessarily.
- Record important decisions, approvals and timestamps.
- Do not include passwords, authentication tokens or other secrets.
- Apply appropriate access controls and retention requirements.
- Keep the incident report and action register linked by incident reference.

## Important

These templates are starting points, not substitutes for legal advice, regulatory guidance or an organisation's approved incident response procedures.
